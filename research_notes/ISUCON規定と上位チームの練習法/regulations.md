# ISUCON 公式レギュレーションの全体像と変遷（ISUCON1〜ISUCON2026）

調査日: 2026-10-31（ISUCON2026 本番当日）。一次情報は isucon.net 公式ブログと github.com/isucon のマニュアル。
**最重要の前提**: 2025年に「ISUCON15」は開催されていない模様（公式ブログのアーカイブに2025年開催の記事なし）。次回大会の名称は「ISUCON16」ではなく **「ISUCON2026 〜Second Stage 変わらない情熱、新たな挑戦〜」**。運営窓口が LINEヤフー から さくらインターネット に移り、2026-10-31 に開催された。

## 1. 形式（予選/本選、時間、チーム人数、通過チーム数、学生枠、賞金）

### Takeaway
ISUCON12（2022）までは「オンライン予選 → 30チーム程度が本選」の2段階だったが、ISUCON13（2023）から「本選のみ・1日8時間・最大700〜1000チームが一斉に競う」単一ラウンド形式に変わり、ISUCON14・ISUCON2026 も同じ形式。チームは1〜3名、一般枠と学生枠があり、賞金は直近2回とも優勝100万円。

### Cited Findings

## 2. 競技環境（クラウド、台数、スペック、構築方法）

### Takeaway
ISUCON11 以降は「各チームが自分の AWS アカウントを用意し、ポータルから配布されるチーム専用 CloudFormation テンプレートで東京リージョンに EC2 を3台（c5.large）立てる」方式。それ以前は年ごとに異なるクラウドが提供されていた。

### Cited Findings
- ISUCON2026: 各チームが自前の AWS アカウントを用意し（既存アカウントも可だが、既存リソースが原因の問題はサポート対象外）、指定 AMI から EC2 を起動する。OS は Ubuntu。台数とスペックはレギュレーションに記載がなく、当日マニュアルで案内 — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
- ISUCON2026 の事前準備（必須）: 全員が Discord に参加すること、ポータルの「競技環境確認」から CloudFormation テンプレートを取得し、東京リージョン（ap-northeast-1）でスタックを作成して SSH で確認すること。期限は 10/27(火) 19:00 で、間に合わないチームは「当日サポート不可」。確認後はスタックを削除すること（放置すると「高額な請求がかかる可能性があります」） — [ISUCON2026 事前準備](https://isucon.net/archives/60111629.html)
- ISUCON14: c5.large ×3、各 gp3 20GB の EBS と EIP、ap-northeast-1。チーム専用の CloudFormation テンプレートをポータルからダウンロードし（共有は禁止）、スタックを作成する — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
- ISUCON13: c5.large ×3、gp3 40GB ×3、EIP ×3、ap-northeast-1。**インスタンスタイプの変更は失格**。複数スタックを作ってもよいが、競技終了時にポータルに複数スタックのサーバーが混在していると失格。セキュリティグループの 22・443・UDP 53 番ポートの変更も失格 — [ISUCON13 当日マニュアル](https://github.com/isucon/isucon13/blob/main/docs/cautionary_note.md)
- ISUCON12 予選: AWS で、各チームが自前のアカウントを用意して EC2 を起動 — [ISUCON12 予選レギュレーション](https://isucon.net/archives/56671734.html)
- ISUCON11 のインフラは AWS の協賛 — [ISUCON11 まとめ](https://isucon.net/archives/55821036.html)
- 過去のインフラ提供元:
  - ISUCON10: サイバーエージェント — [ISUCON10 まとめ](https://isucon.net/archives/54704557.html)
  - ISUCON9: Alibaba Cloud — [ISUCON9 まとめ](https://isucon.net/archives/53570241.html)
  - ISUCON8: GMOインターネット — [ISUCON8 まとめ](https://isucon.net/archives/52388756.html)
  - ISUCON7: さくらインターネット — [ISUCON7 まとめ](https://isucon.net/archives/50949022.html)
  - ISUCON6: Microsoft Azure — [ISUCON6 まとめ](https://isucon.net/archives/48465737.html)
  - ISUCON5: 予選は GCP、本選はテコラス — [ISUCON5 まとめ](https://isucon.net/archives/45166636.html)
  - ISUCON3: データホテル — [ISUCON3 まとめ](https://isucon.net/archives/41252102.html)

### Inferences
- ISUCON2026 も CloudFormation と ap-northeast-1 で構築する方式が確認されており、ISUCON13・14 と同じ系統と考えられる。練習では「c5.large（2vCPU・4GiB）×3台」を前提にするのが妥当。ただし ISUCON2026 の当日スペックは未確認。
- AWS の利用料は参加者が負担する（参加規約の「クラウド費用は参加者負担」）。練習でスタックを放置しないこと。

### Gaps
- ISUCON2026 当日の台数とインスタンスタイプは、当日マニュアル（github.com/isucon/isucon2026）を取得できず未確認。

## 3. 採点（ベンチマーカー、スコア計算、fail条件、追試、失格）

### Takeaway
ポータルからベンチを依頼し、**競技中に最後に実行したベンチのスコアが最終スコアになる**（ベストスコアではない）。最後のベンチが fail なら記録なし。競技終了後に運営が「全台を再起動 → ベンチ再実行」の追試を行い、fail、スコアが最終スコアの75%以下、データ消失、envcheck の失敗などがあると失格。ISUCON14 では約270チームが FAIL 扱いになった。

### Cited Findings
- 共通ルール（ISUCON12〜2026）: 追試では再起動を行い、再起動の順序は保証されない。ベンチが正常に完了しない、競技中のスコアに近い結果が再現されない、結果に捏造があると判断された場合は失格（判断基準も公開される） — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html), [ISUCON12 予選レギュレーション](https://isucon.net/archives/56671734.html)
- 維持すべき条件（共通）: 競技用メンテナンスコマンドとの互換性、再起動後もアプリが正常に動くこと、ベンチ中に書き込んだデータが再起動後も取得できること — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
- ISUCON14 のベンチの流れ: 初期化（30秒）→ 整合性チェック → 負荷走行60秒 → 最終チェック。初期化や整合性チェックの失敗は即 FAIL。負荷走行中にクリティカルエラーが出るか、warning が200件以上になると中断。スコアは「配車位置から乗車地点までの距離×0.1＋乗車地点から目的地までの距離＋完了したライド数×5」 — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
- ISUCON14 の最終スコアは、競技中に最後に実行したベンチのスコア。それが fail なら最終スコアなしで、表彰対象外 — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
- ISUCON14 の追試では、3台すべてを**2回**再起動する。envcheck に合格すること、3台が同一 VPC にあることが必要。ベンチが FAIL か最終スコアの75%以下なら再実行し、計3回とも NG なら失格。再起動後にデータを保持していること、フロントエンドが参照実装と同じ構造で表示できることも条件 — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
- ISUCON14 の結果: 約270チームが FAIL（最終スコア0が117チーム、追試 NG が153チーム）。追試 NG の主な理由は「負荷走行NG」と「データ保持NG」。ほかに再起動NG、envcheck NG、目視確認NG（画面が真っ白など）があった — [ISUCON14 全チームスコア](https://isucon.net/archives/58837992.html)
- ISUCON13 のベンチの流れ: `POST /api/initialize`（タイムアウト42秒）→ 整合性チェック → 負荷走行60秒 → 最終チェック。スコアはベンチ1回あたりのチップ（投げ銭）総額。6分以上止まったベンチは自動で ABORT。競技終了後から結果発表までにサーバーで作業すると失格。追試では全台再起動後に fail、スコアが75%以下、envcheck 失敗なら失格。上位チームは再起動後のデータ保持も確認される — [ISUCON13 当日マニュアル](https://github.com/isucon/isucon13/blob/main/docs/cautionary_note.md)
- ISUCON13 の fail 内訳は、再起動後スコア0が約51チーム、最終スコア0が約85チームなど（ページ上のリストを集計した概数） — [ISUCON13 受賞チーム](https://isucon.net/archives/57993937.html)
- ISUCON13 の最終順位は「競技中の最後のスコア」で決まると明記 — [ISUCON13 レギュレーション](https://isucon.net/archives/57768216.html)

### Inferences
- 実戦上の教訓: (1) 終了直前には必ず成功するベンチで終える（最後が fail だと0点）。(2) 全台の再起動テストを競技中に必ず行う。(3) オンメモリキャッシュを使うなら、再起動後の復元（データ保持）を保証する。(4) envcheck や運営が用意したファイル・ユーザーには触れない。
- 「追試スコアが最終スコアの75%以下で NG」という基準は ISUCON13・14 で共通。ISUCON2026 も同様の可能性が高い（未確認）。

### Gaps
- ISUCON2026 のスコア計算式と fail 条件は、当日マニュアルを取得できず未確認。

## 4. 許可・禁止事項（言語、ミドルウェア変更、外部サービス、連絡、生成AI）

### Takeaway
参照実装の言語は Go/Perl/PHP/Python/Ruby/Rust/Node.js（ISUCON12 は Java も）。URI、レスポンス構造、JS/CSS、メディアファイル以外はほぼ自由に変更できる（言語・ミドルウェアの変更、他言語での再実装も可）。**生成AIの利用は ISUCON13 から明文で許可**されており、ISUCON14・2026 も同じ文言（「開発において、AIを活用したコードの分析、生成等を利用しても構わない。」）。ただし、ベンチ対象の処理を外部リソースに委譲することは禁止で、競技中にチーム外の人と問題について話すことも禁止。

### Cited Findings
- 提供言語:
  - ISUCON2026: Go、Perl、PHP、Python、Ruby、Rust、Node.js（予定）。言語ごとの性能が同等であることは保証されない — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
  - ISUCON2026 では参考実装の移植協力者を募集した — [公式ブログ (2026-09-28)](https://isucon.net/archives/60075872.html)
  - ISUCON12 予選は Java を追加して8言語 — [ISUCON12 予選レギュレーション](https://isucon.net/archives/56671734.html)
- ISUCON14 の言語別チーム数（787チームを集計）: Go 549、Node.js 69、Ruby 64、Python 48、Rust 27、PHP 24、Perl 4。上位30チームでは Go が26チーム — [ISUCON14 言語比率](https://isucon.net/archives/58847106.html)
- 変更不可（共通）:
  - アクセス先の URI（サーバー側で生成する ID は、文字種を変えなければ生成方法を変えてよい）
  - レスポンス構造（表示に影響しない空白は可）
  - JS/CSS の内容
  - メディアファイルの内容

  変更可（共通）: サーバーの役割、DB スキーマとインデックス、DB ミドルウェアの入れ替え、キャッシュやジョブキューによる遅延書き込み、他言語での再実装。当日マニュアルはレギュレーションより優先される — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
- 生成AI:
  - ISUCON2026 は許可事項に「開発において、AIを活用したコードの分析、生成等を利用すること」、注記に「開発において、AIを活用したコードの分析、生成等を利用しても構わない。」と記載 — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
  - ISUCON14 も同じ文言 — [ISUCON14 レギュレーション](https://isucon.net/archives/58657116.html)。マニュアルにも AI によるコード分析・生成は許可と記載 — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
  - ISUCON13 も同じ文言 — [ISUCON13 レギュレーション](https://isucon.net/archives/57768216.html)
  - ISUCON12 予選レギュレーションには AI の記述なし — [ISUCON12 予選レギュレーション](https://isucon.net/archives/56671734.html)
  - ISUCON2026 参加規約にも AI 固有の条項はない。サードパーティ製のツールやデータはライセンスを遵守する、という一般条項のみ — [ISUCON2026 参加規約](https://isucon.net/archives/59967038.html)
- 外部リソース:
  - ベンチ中に認められたサーバー以外を使うこと（他インスタンスへの処理委譲など）は禁止。モニタリング、テスト、開発には PC や外部サーバーを使ってよい — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
  - ISUCON13 では、外部計算資源の利用は「スコアを向上させる効果をもたらさない」範囲に限られる。デプロイ用の外部コンテナレジストリ（ECR など）は利用可だが、競技終了まで他チームから見えないようにする — [ISUCON13 当日マニュアル](https://github.com/isucon/isucon13/blob/main/docs/cautionary_note.md)
  - ISUCON14 も外部コンテナレジストリの利用は可 — [ISUCON14 マニュアル](https://github.com/isucon/isucon14/blob/main/docs/manual.md)
- 情報公開とコミュニケーション:
  - 競技終了まで、問題内容や計測方法の公開・共有（推察できる発言を含む）は禁止。他チームとの結託も程度を問わず禁止。競技中にチーム外の人と問題について話すこと（SNS を含む）も禁止。ログインが必要なポータルの内容は公開情報に当たらない。提供されていないサーバー（ベンチマーカーなど）へのアクセスを試みることも禁止 — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)
  - 連絡手段: 全体アナウンスは Discord、競技中の質問はポータル、競技前後の質問は Discord。全員が Discord にログインし、通知を設定しておく義務がある。競技中の質問への回答は、原則として全選手に公開される — [ISUCON2026 レギュレーション](https://isucon.net/archives/59966826.html)

### Inferences
- 生成AIの利用は「開発における分析・生成」として明文で許可されており、Claude、ChatGPT、Copilot などの外部 SaaS を使ってもよいと読める。ただし、次の2点に注意が必要（いずれも推論）:
  - (a) アプリの実行時処理を外部 API に委譲するとスコア向上に寄与するため、外部リソース禁止に当たる。
  - (b) 「チーム外の人物」との問題のやり取りを禁じる条項は人間を想定しているが、AI エージェントにコードを送ること自体は禁止されていない。
- AI の利用条件は3大会連続で同じ文言。次回も大きく変わる兆しはない。ただし、実施年のレギュレーションで必ず再確認すること。

### Gaps
- 競技中に外部 LLM へ問題コードやログを送ってよいかという点（「外部への情報共有」との関係）に、明示的な規定はない。不安な場合は、当日ポータルで質問するのが確実。

## 5. 参加登録（受付開始時期、埋まる速さ、スケジュール）

### Takeaway
受付は数日おきの3回（第1〜第3次）に分けた先着順。ISUCON2026 は 7/28・8/1・8/5、ISUCON14 は 9/24・9/28・10/2。人気が高く、各回すぐに埋まると考えたほうがよい。スポンサー企業には「参加確定枠」があり、優先して登録できる。

- ISUCON2026 の受付: 7/28(火) 20:00 に300枠、8/1(土) 12:00 に300枠、8/5(水) 10:00 に335枠（いずれも予定）。受付予定日は途中で変更された — [ISUCON2026 開催決定](https://isucon.net/archives/59917350.html)

### Inferences
- ISUCON2026 の上限は1000チームだったが、実際の参加は856チームだった。このため ISUCON2026 は以前より取りやすかった可能性がある（推論）。それでも、受付開始時刻にチーム代表が待機しておくのが無難。
- 次回が2027年に開催される場合、告知は夏頃、受付は本番の約2〜3か月前と予想される（未確認）。

### Gaps
- ISUCON2026 の各回が何分で埋まったかは、公式記事で確認できなかった。
- ISUCON2027 の開催告知は、2026-10-31 時点で見当たらない。

## 6. 年ごとの主なルール変更（一覧）

### Takeaway
大きな変化は3つ。(1) ISUCON11 から AWS を自前アカウントで使う方式になった。(2) ISUCON13 から本選のみの1日形式になった。(3) ISUCON13 から生成AIの利用が明文で許可された。加えて、2026年は運営窓口の交代と名称の西暦化があり、2025年は開催されなかった。
